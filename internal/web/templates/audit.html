Handing this to the rest of the estate

The chain above is this installation's own record: tamper-evident on this box, and only on this box. A sealed record somebody else can verify without trusting this process is a different thing, and trailryx is where it goes.

{{.Mapped}} of the {{.Emitted}} events on the stream are in the estate's shared vocabulary and can be read by any service in it. The other {{.OwnOnly}} are this console's own: a finding triaged, an agent hired, a sprint planned. Those have no equivalent in a vocabulary about runs, and being refused downstream is the right answer rather than a gap.

trailryx-node events --file {{.Stream}} \
  --tenant costcrew --trust-domain costcrew.local --data /where/the/plane/lives

Safe to run on a schedule: it keeps a cursor, reads only what is new, and writes the new position only after the seal. Then trailryx-node read --all --pack evidence.pack writes what an auditor takes away, and trailryx-verify evidence.pack checks it with code that is not this console's and not trailryx's node either.

Watching it live

genaryx and heraldyx both tail this same file, and neither needs a command: point them at it. genaryx tails a DIRECTORY and keys each source off the file name, so the stream has to be called costcrew.ndjson and sit in the bus its environment descriptor names. Start this console with -stack-events <that directory>/costcrew.ndjson and the events appear on its console within seconds of being written.

genaryx accepts all {{.Emitted}} of them, including this console's own vocabulary: its schema asks only that a type be a non-empty string. trailryx accepts {{.Mapped}}. Neither is wrong; one is a live view and the other is a sealed record, and they disagree about what belongs in a record.
