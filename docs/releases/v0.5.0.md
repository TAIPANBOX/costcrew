# CostCrew 0.5.0

The AI spend the console reads from TokenFuse is counted once however many times the
same trace is exported, and a call refused for identity is filed under the
credential that made it, never under the agent it claimed. Several pages that said
something untrue now say what is so: what a model is sent, whether a refused plan
request was paid for, what a self-hosted engine is and what it used, which business
unit a customer unit is charged under. Read the upgrade notes first.

## What changed (costcrew#112 to #119)

**AI spend that is counted once and filed under the right name**

- **A re-export of the same calls supersedes the earlier rows (#115, invariant 89).**
  `ai_calls` was keyed by file hash and row number, so exporting the same TokenFuse
  trace again, as an upgrade to TokenFuse 1.7.0 invites, counted every call twice
  and kept a victim's misattributed identity refusals beside the key's. A call now
  has an identity two exports agree on (run, settle instant, model, tokens, amount,
  blocked; not the agent, which 1.7.0 moved), and an export from 1.7.0 or later is
  the copy kept, whichever file the folder lists first. `x_key_id` and
  `x_block_reason` are stored. A refusal that names no agent and no key because
  client keys were off is reported as the gateway's refusal, not as bad data. The
  connector page now shows what the last import read.
- **A credential reads as a credential and a blocked call says why (#116, invariant
  90).** `/ai` labels a `key:` row "credential, not an agent", counts blocked calls
  by the gateway's reason, says an identity refusal reserved and spent nothing,
  notes a month that mixes exports from before and after TokenFuse 1.7.0, and the
  ai-spend analyst's packet carries the same reasons. The pages that said no gateway
  reader exists point at the TokenFuse connector, and a gateway agent id is no
  longer linked to a crew card that does not exist.

**Pages that say what is so**

- **What a model is sent (#117, invariant 91).** `/engines` and `/sprint/plan` show
  the `-prompt-data` mode and, under `masked` or `aggregates`, that the sprint goal a
  person types is withheld. A refused plan request says whether it was refused
  before the call (nothing spent), failed at the gateway (nothing booked), or was
  made and paid for and had its answer refused.
- **The typed hint on the task (#118, invariant 92).** The task page shows typryx's
  hint for the anomaly it came from; the anomaly's panel names typryx's answer id,
  the fields sent and the count held back, and no longer says typryx saw fields when
  nothing was sent.
- **The local engine (#119, invariant 93).** Its readiness is costcrew-run's, not the
  console's environment; its setup text names costcrew-run's flags and
  `-local-parallel`; the engines page counts its own catalogue; the forms name
  engines; a local run's tokens are recorded per task (`tasks.live_tokens`) and shown
  on the task page and the agent card instead of "0.00 against a per-task guard".
- **Units and teams (#119, invariant 94).** A customer unit's page names the business
  unit its stamped rule charges it under; `/teams` lists the customer units and
  calls a team's own unit its business unit; the chargeback units panel names the
  month it shows instead of "today".
- **Four small sentences (#119, invariant 95).** The reconciliation states that it
  matches a model by its exact name; the two provider usage connectors are listed as
  folders; the TokenFuse connector asks for a path and links to `/ai`.

**Earlier in this release**

- **Decisions recorded as paraphrases (#112, invariant 83).** No tracked file quotes
  the owner or attributes a decision by name; a gate holds it.
- **One local task at a time by default (#114, invariant 84).** `costcrew-run
  -local-parallel` (default 1) sets how many local-engine tasks run at once, so a
  server that answers one request at a time no longer times tasks out; `-only` names
  the task's own refusal; a later local round is never counted below the one before.
- **Four small defects (#113, invariants 85 to 88).** A month from the address bar is
  a bound parameter; the rightsizing, budget recommendation and SaaS seats readers
  bound their refusal lists and name a link they did not follow; one rule judges a
  unit's name; the example pseudonym a prompt shows can never be a real team's.

## Upgrade notes

- **Import the gateway folder once after upgrading.** An installation that already
  holds two exports of the same trace counts those calls twice until its next
  import, which keeps each call once. Nothing else is needed; every import reads the
  whole folder.
- **New columns, added at start:** `ai_calls.key_id`, `block_reason` and a virtual
  `call_key`; `connections.last_import`, `last_import_result`; `tasks.live_tokens`,
  `live_token_ceiling`; and, with typryx configured, `anomalies.hint_fields_sent`,
  `hint_held_back`. No data is rewritten.
- **A TokenFuse 1.7.0 export with client keys off** can carry refused calls with no
  agent and no key. They are not imported, and the import says why.
- **The local engine never reads "ready" on `/engines`** however the console's own
  environment is set: it is set up where costcrew-run runs.
- **No flag was added or removed on the console.** `costcrew-run` gained
  `-local-parallel` in #114.

## Not proven in this release

- No real TokenFuse 1.7.0 export was read: the fixtures follow the shape its release
  notes and its own export tests describe.
- No live model call was made for any change here; plan-ask and runner behaviour were
  exercised against local fake servers.
