# CostCrew 0.4.0

The console reads real cloud bills, signs people in through the organisation's
identity provider, can run the whole crew on a model the organisation hosts itself,
and decides how much of the bill a model is ever shown. The console's own storage and
HTTP edge were hardened, and a thinking model's reasoning is now counted as output.
Several behaviours change on upgrade, so read the upgrade notes first. This release
was approved by the owner.

## What changed (costcrew#91 to #110)

**Reading real money**

- **Plain-FOCUS folder readers for AWS Data Exports and the GCP billing export (#98,
  invariant 67).** Exact money through integer micros (E notation expanded textually,
  no float), every charge category kept under its own name, so a Purchase, Tax or
  Credit never counts as usage; the team comes from a configurable tag. Proven on a
  real AWS FOCUS 1.0 export.
- **Showback per customer unit (#99, #74).** An `allocation.rule` can be keyed on a
  customer unit (the gateway's `x_unit`), proposed by the chargeback analyst and
  applied only by a person's stamp; the crew-cost KPI states the signed money found.
- **Provider usage reconciliation (#105, invariants 80, 81).** The console reads the
  vendors' own usage exports from a folder and reconciles them against the gateway's
  rows. A new binary, `costcrew-usage`, does the admin-key requests, so the console
  itself still makes no outbound call.

**Where the crew runs and what it may see**

- **A local engine (#102, invariants 72, 73).** `local` calls any server that speaks
  the OpenAI chat-completions route (Ollama, vLLM, LM Studio, llama.cpp):
  `-model-url`, `-model-name`, optional `COSTCREW_MODEL_KEY`. A model on your own
  hardware is bounded either by a price (`-local-price-in`, `-local-price-out`) or by
  `-max-run-tokens`; at a price of 0 a run without a token ceiling is refused. Through
  `-gateway-openai` the calls are metered by TokenFuse like any other.
- **`-prompt-data full|masked|aggregates` (#106, invariants 70, 71).** `full` is the
  default and changes nothing. `masked` replaces every name the store holds with a
  stable keyed token before a prompt or tool result leaves the process, withholds
  free text, and does not offer the SQL tools; drafts are turned back into real names
  before they are saved. `aggregates` sends totals only. The key is
  `prompt-data.key` in the data directory, mode 0600.
- **A typed hint before an analyst works an anomaly (#108, invariants 76, 77).**
  Optional: `-typryx-url` / `COSTCREW_TYPRYX_URL`, key in `COSTCREW_TYPRYX_KEY` only.
  The hint obeys `-prompt-data`.
- **A thinking model's reasoning is output (#110, invariant 82).** Usage where
  `total_tokens` exceeds prompt plus completion (Gemini on Vertex reports reasoning
  outside `completion_tokens`) is counted as output in the token ceiling, the runner's
  own price and the bus. The matching gateway fix is on TokenFuse's main branch (tokenfuse#367), not yet in a release.

**Accounts, storage and the HTTP edge**

- **Sign-in through the organisation's identity provider (#103, invariants 74, 75).**
  OpenID Connect with discovery, signed ID tokens and PKCE; `-oidc-*` flags and their
  `COSTCREW_OIDC_*` twins; the client secret only from the environment or a file.
  Roles come from a claim mapping with no default; `-oidc-only` turns password
  sign-in off except for accounts set with `-set-password`.
- **Session tokens are stored hashed; every failed sign-in says the same thing; the
  console's own files are private; the console's egress is gated (#96, invariants
  61 to 64).**
- **The HTTP edge (#97, invariant 59).** Security headers and a content security
  policy on every response, request bodies capped at 1 MiB (413 before any handler),
  read, write and idle timeouts on the server, the results export escaped.
- **Downloads are data (#104, invariants 78, 79).** Every CSV cell is typed and a
  value that starts a spreadsheet formula is neutralised; downloads carry
  `Cache-Control: no-store`; `x_unit` is bounded.
- **The runner names the crew's owner to the gateway, and a block placed while a call
  is in flight is kept (#95, invariants 65, 66).**

**Image and supply chain**

- **The image holds every binary a deployment runs (#94, #105, invariant 60):**
  `costcrew`, `costcrew-run`, `costcrew-enforce`, `costcrew-idryxsource` and
  `costcrew-usage`, on base images pinned by digest; govulncheck in CI; Dependabot for
  Go modules and Docker.

Housekeeping since 0.3.0: agent-stack-go v1.1.0 (#91), README (#92), the teeth
harness reads needles safely under pipefail (#93), tools coverage from 0% to 94-99%
(#100), Go module updates (#109).

## Upgrade notes

- **Everybody signs in again once.** The sessions table moves from clear-text tokens
  to hashes; old sessions cannot be carried over and are ended at the first start
  (journaled as `sessions_reset`). Accounts are untouched.
- **The data files become private.** `app.db`, its `-wal` and `-shm`, and the journal
  are set to 0600 at start; a data directory the console creates is 0700; an existing
  directory keeps its mode. The `-stack-events` file and the passport files stay
  readable by the services that read them.
- **With a gateway configured, an analyst with no owner is refused before the call**
  (#95), naming it: give every analyst an owner before running behind TokenFuse.
- **Request bodies over 1 MiB are refused with 413** (the intake upload keeps its own
  larger cap).
- **New settings**, all declared in `components.json`: on the console `-oidc-*`,
  `-prompt-data`, `-typryx-url`, `-typryx-max-asks`; on the runner `-model-url`,
  `-model-name`, `-local-price-in`, `-local-price-out`, `-max-run-tokens`,
  `-prompt-data`, `-typryx-url`; the `costcrew-usage` binary. None is required; with
  none set the console behaves as 0.3.0 apart from the notes above.
- **Known limits found on real infrastructure before this release** and not fixed in
  it: the runner keeps four tasks in flight, so a local model server that answers one
  request at a time can time tasks out (run with `-only`, or give the server parallel
  slots); the gateway's FOCUS export carries no key id, so a refused impersonation
  attempt is attributed to the agent id it claimed.
