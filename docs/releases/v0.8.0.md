# CostCrew 0.8.0

Every agent the console names now sits under a `costcrew` segment of its trust domain: `agent://<host>/costcrew/<name>`, where it used to be `agent://<host>/<name>`. A gateway client key bound to `agent://<host>/costcrew/*` can then cover the crew and nothing else in the same trust domain. This release is breaking for every installation that names an analyst by its id. Read the migration notes before you upgrade.

## What changed (costcrew#151)

**Analyst identities**

- **Every analyst, the supervisor and the detector are named under the path.** The id is built in one function, `stack.AgentURI`, and every consumer builds through it: the Agent Passport documents, the events on the bus, the `x-fuse-agent-id` header on gateway calls, the on-behalf-of chain, and the idryx agents source that `costcrew-idryxsource` writes. The host is unchanged, so the trust domain the consumers match on is unchanged.
- **A host that cannot produce valid ids stops the console at start.** When `-stack-events` is set, a host with characters outside lower-case letters, digits, dots and hyphens, or one long enough to push an analyst's id past agent-passport's 255-byte limit, is refused before anything is written. Before this release such a host was accepted, and the events it wrote carried ids that consumers refuse.
- **The passport sweep removes only this console's passports.** A passport of another agent in the same trust domain, outside the costcrew path, is left alone.

**Tests and docs**

- Five new tests hold the path, the length limit, the sweep and the gateway chain. The rest of the suite was updated where it pinned the old form.
- The README says what the path means for a gateway key and gives the upgrade steps.
- Stated counts restated: 1820 tests in 32 packages, 622 teeth cases, 629 scenarios in 76 files.

## Breaking

- **Agent ids change form.** `agent://<host>/<name>` becomes `agent://<host>/costcrew/<name>` for every analyst, for the supervisor and for the detector. Passports, events, gateway headers and the on-behalf-of chain all carry the new form from this release.
- **Old events keep their old ids.** Nothing on the bus is rewritten. A query over the bus that spans the upgrade must match both forms.
- **Old passports of departed analysts are not removed.** An analyst removed before this release keeps its old-form passport, and the sweep does not match it.
- **A host the console cannot use is refused at start** when `-stack-events` is set (see above).
- **A person credited on the bus takes the path too.** The console builds the id of every actor the same way, so a replacement of the generated estate, or an option applied or refused by an owner or an admin, is credited to `agent://<host>/costcrew/<username>`. A person's id was already an `agent://` id before this release, and it is still one. Giving people their own subject form is a separate change and is not in this release.

## Migration

Nothing changes for an installation that never names an analyst by its id. For one that does:

- **Gateway keys and identity maps.** Any entry that binds an analyst's id as `agent://<host>/<name>` must name `agent://<host>/costcrew/<name>`. To cover the whole crew with one key, bind it to the prefix `agent://<host>/costcrew/*`. Rebind before the first run of 0.8.0: once a key is bound to the prefix, a call carrying an id outside it is refused.
- **Wardryx policies.** A policy whose target names an analyst by its id must name the costcrew form.
- **Dashboards and saved queries.** A filter on `agent_id` that names an analyst must match the new form. A query over a period that spans the upgrade must match both forms, since the bus keeps both.
- **Passports.** Analysts still on the roster get new passports under the same file names, which overwrites the old ones. Delete by hand, from `-stack-passports`, the passports of analysts removed before 0.8.0. The sweep removes only passports under the costcrew path, so it will not remove those.
- **idryx.** Rebuild the agents source with `costcrew-idryxsource` after the upgrade, so it carries the new ids. This release does not remove ids another system has already loaded. Remove those in that system if its graph should not show departed analysts under both forms.
- **Start-up refusal.** If the console refuses to start with a host error, give `-stack-host` a lower-case host made of letters, digits, dots and hyphens. The refusal names the host it refused.

## Not proven in this release

- A running gateway refusing a call under a key that the path does not cover. The tests check the ids the console builds, not a gateway's refusal.
- Consumers of the old ids outside this repository. A text search of the sibling repositories' main branches found no gateway binding of an analyst id in either form. That search does not cover unmerged work.
- A live bring-up of a stack with the new ids. The gates ran on test fixtures and generated data only.
