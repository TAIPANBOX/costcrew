# CostCrew 0.9.0

## Upgrade first: the stack events file is readable by its group, not by every account

0.9.0 is a minor because of this change. The move to agent-stack-go v2 (below) creates the file named by `-stack-events`, for example `/var/lib/stack/events/costcrew.ndjson`, with mode `0640`, not `0644`. The owning account and its group can read it. Any other account cannot. A new file is also refused in a directory the costcrew process does not own. Before you start 0.9.0:

- If another service reads the stack events file from a different account, add that account to the file's group, or have it run as the owner. A reader outside the group gets a permission error, and nothing on the bus is lost.
- If the file is in a directory that costcrew's user does not own, the file must be created by that user, or the directory's owner must change. An existing file is opened as it is.
- A bus directory shared with other services and not owned by costcrew's account gets no new stream file unless each file is created beforehand by the uid of the service that writes it. Check the owner of the bus directory and the mode of each stream file in it before you start 0.9.0.
- Passports and directories keep their modes: passports `0644`, directories `0755`.

## Changed since 0.8.0

- **The agent-stack-go pin moves to the v2 module path, v2.0.0 (#153).** The shared wire-type import moves to `github.com/TAIPANBOX/agent-stack-go/v2`. The stack events file's mode is the change described above. The test that checks shared files now requires exactly that mode for the stack events file, and keeps its checks for the passports and the two directories.
- **The image is signed in the legacy format (#154).** The image sign step adds `--new-bundle-format=false --use-signing-config=false`, with a comment above it, because the cluster admission controller (policy-controller v0.15.1) reads only the legacy `.sig` tag. cosign stays at v3.1.3. Remove both flags when policy-controller reads bundles.

No other commit lies between the 0.8.0 tag and this release. The agent id form, which is the 0.8.0 breaking change, is unchanged here.
