# CostCrew 0.7.0

The console can now read its gateways' export folders from its own start-up flags, and it tells the two doors of a TokenFuse gateway apart. It shows which calls the gateway forwarded under identity warn mode, which runs switched model, and which spend was priced at the gateway's fallback rate. The supervisor no longer applies an option whose figure disagrees with the anomaly it closes, and three silent errors in money and import are fixed. Nothing here is breaking. Read the migration notes before you upgrade.

## What changed (costcrew#123 to #146)

**Supervisor decisions (#146, invariant 108)**

- **An option tied to an anomaly is judged on the anomaly's recorded excess.** Before this release, the supervisor's threshold read the figure the analyst wrote into the option, so an option could close an anomaly on a figure that did not match it, and nothing recorded the disagreement. The threshold now reads the excess the anomaly recorded. An option whose figure does not equal that excess, to the cent, is carried to the owner with both figures and the reason on the decision request. It is not applied.

**Fixes to money and import**

- **An amount too large for 64 bits is refused.** `Parse` and `ParseMicros` multiplied the whole part by its scale and wrapped silently, so an oversized amount in a TokenFuse export was stored as a small, wrong amount. Both now refuse it. (#126)
- **A call's cost is rounded once, never truncated (invariant 105).** The estimate for the crew's own live calls truncated in floating point: 1,000 tokens in at 3 per million and 500 out at 15 came to 10,499 micro-units, not 10,500. It now multiplies and rounds once.
- **Supersede is per gateway door (invariant 106).** When both doors' exports held the same call, the second file read deleted the first door's row, so one blocked call was counted once. A re-export now replaces only rows from the same door.

**AI spend: identity, runs, doors and prices (invariants 100 to 103)**

- **Calls forwarded under identity warn mode are marked (#130, invariant 100).** TokenFuse 1.8.0 writes the identity check's finding on a call the gateway let through in warn mode. The console keeps it, counts those calls and their spend per agent, team and run, and says so on `/ai`. An export without the column is said to be unable to tell.
- **A runs page (#131, invariant 101).** `GET /ai/runs` lists each run of the month, largest spend first, with every model it used in the order first called and each model's share of the run's spend. A run that changed model is no longer named by its last model alone.
- **Each gateway door is its own source (#132, invariant 102).** The tokenfuse-focus connector takes an optional second folder, the OpenAI-wire door's export. Each row records the folder it came from, `/engines` names the doors, and `/ai/runs` marks a month read from two doors. The same folder given as both doors is refused.
- **Fallback-priced spend and personal data are shown apart (invariant 103).** A call the gateway priced at its fallback rate is kept out of spend and shown on its own line. Personal data the gateway's scanner let through is named by kind and count. Its values are never shown or quoted.

**Gateway export folders read by a launcher (invariant 104)**

- **New console flags:** `-focus-dir` (`COSTCREW_FOCUS_DIR`), `-focus-dir-openai` (`COSTCREW_FOCUS_DIR_OPENAI`), `-focus-every` (default `15m`, where `0` reads once at start) and `-focus-replace-generated`. The folders are read at start and on the interval. A misconfiguration stops the console from starting.
- An automatic import that is refused is recorded on the connector's page, so the page says why.

**Cloud FOCUS drop (#126)**

- **New binary, `costcrew-cloudability`, in the image.** It writes a month-to-date FOCUS 1.1 drop of agent spend for Apptio Cloudability's Custom Data FOCUS ingress into a local folder: one row per UTC day, unit, agent, model and credential, money in exact micro-dollars, blocked calls counted and never charged. It makes no network call, and syncing the folder is the operator's job. Its flags are `-in`, `-out`, `-root-dir`, `-sub-dir`, `-vendor`, `-prefix`, `-month`, `-billing-account-id` (required) and `-billing-account-name`.

**Prices (#145)**

- **OpenRouter's Anthropic model is Sonnet 5.** OpenRouter no longer lists an endpoint for `anthropic/claude-sonnet-4`, so the engine's third model is now `anthropic/claude-sonnet-5`, priced at 2.20 / 11.00 per million tokens: the higher of its two endpoint prices, since OpenRouter picks the provider.

**Dependencies and CI (#123, #124, #136, #142, #144)**

- `agent-stack-go` moves to v1.3.0. Its v1.2.0 step takes an exclusive file lock for every append, so two processes appending to one events file no longer fork its hash chain. v1.3.0 applies the same lock to the plain writer. No exported identifier moved.
- Go module bumps (the gomod group, #124) and GitHub Actions bumps (#123).
- The gate harness runs as four parallel shards (#142). The `teeth` job is still the required check, and it fails unless all four shards pass.

**Tests and docs**

- Test-only changes lift four packages past 90% statement coverage: `internal/web` from 81.2% to 90.2%, `internal/finops` from 79.9% to 91.1%, and `internal/promptfixture` and `internal/deliver` past 90% as well.
- README corrections (#129): all 23 wire types are in the SPEC table, `enforced: false` is stamped only on `budget_threshold` events, the runner writes `tool_call` to the bus, and the Cadence section matches the manifests.
- Stated counts restated: 1815 tests in 32 packages, 615 teeth cases, 624 scenarios in 75 files.

## Breaking

None. No flag, route, environment variable, column or stored value is removed or renamed. The model that left the OpenRouter engine, `anthropic/claude-sonnet-4`, had no endpoint left to serve it.

## Migration

Nothing has to change for an existing installation. These are the changes an operator can see:

- **Four nullable text columns on `ai_calls`, added at start:** `identity_reason`, `door`, `price_basis` and `pii_findings`. Rows read before this release keep NULL. An older row is read as the main door, and an older export is said to be unable to tell the identity or price basis of its calls. No data is rewritten.
- **Two doors, set once.** If the OpenAI-wire gateway writes its own export, give its folder as `-focus-dir-openai`. Give the same folder as both doors and the console refuses to start.
- **Generated estate.** With `-focus-dir`, the first import that finds real calls does not replace the generated estate unless `-focus-replace-generated` is set. Until then nothing is imported from the folders.
- **Counts from before this release can be low.** Where two doors held the same blocked call, the second door's import removed the first door's row. The upgrade does not rebuild rows an earlier import removed.
- **Oversized amounts are refused.** An export carrying an amount that does not fit in 64 bits is now refused, where before it was stored as a small, wrong amount. If one turns up, check the exporter.
- **Live cost estimates can be one micro-unit higher.** The rounding fix raises an estimate by at most one micro-unit per call. No stored figure is recomputed.
- **The supervisor carries more options.** An analyst's option tied to an anomaly, whose figure is not exactly the anomaly's recorded excess, is carried to the owner instead of applied. The packet prints that excess in whole cents, so an analyst that copies it exactly is applied as before. An analyst that writes dollars or rounded cents will see more carried decisions.
- **The OpenRouter model changed.** Anything that names `anthropic/claude-sonnet-4` on OpenRouter should name `anthropic/claude-sonnet-5`.
- **A new binary in the image.** `costcrew-cloudability` is in the image at `/usr/local/bin`. Nothing runs it unless you do.

## Not proven in this release

- Nothing here has been loaded by Apptio Cloudability. The drop is checked against this repository's own table of FOCUS 1.1 columns.
- Whether a live model copies an anomaly's excess exactly into its option. The supervisor's rule assumes it, and no live run measured it.
- The gates ran on the generated estate and on test exports. No live gateway traffic was part of this release, so the identity, door and price-basis columns are proven against the columns as the tests write them.
- Whether the rounding change moves real spend, beyond the worked example in its test.
