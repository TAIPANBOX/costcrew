# CostCrew 0.10.0

0.10.0 is a minor because it changes three defaults and adds refusals. A console started with no settings now sends masked prompt data, refuses to listen on an address other machines can reach unless TLS is in front or plain HTTP is named, and judges its session key by owner and mode. Read the first section before you start 0.10.0.

## Upgrade first: three defaults that change a running installation

- **Prompt data is masked by default, for `costcrew` and for `costcrew-run`.** A binary started without `-prompt-data` or `COSTCREW_PROMPT_DATA` replaces every team, desk, service, agent, person, invoice, vendor and resource name with a stable token before a prompt leaves the process, and withholds typed free text, the sprint goal included. To keep sending full prompts, pass `-prompt-data full` or set `COSTCREW_PROMPT_DATA=full` on each binary that calls a model. Keep `<data>/prompt-data.key`. The first start in masked mode creates it with mode 0600, and the tokens come from it: a new key gives every name a new token.
- **A console on an address other machines can reach needs TLS in front or an explicit choice.** Any `-addr` that is not loopback (`0.0.0.0:8321`, `:8321`, a LAN address) refuses to start unless `-behind-tls` is set, with a TLS proxy in front, or `-insecure-http` says plain HTTP there is intended. A launcher that runs the console with `-addr 0.0.0.0` must put TLS in front and set `-behind-tls`, or set `-insecure-http`. Without one of the two it will not start.
- **The session key is judged by its owner and mode, and an unreadable key stops the start.** `<data>/.session-secret` must be a regular file that this account owns at mode 0600 or stricter, or, when the console runs as another account, one that root owns at 0640 or stricter. Links, fifos and files owned by anyone else refuse the start. A key this account cannot read is no longer replaced with a new one.

## Breaking

- Prompt data defaults to `masked` for `costcrew` and `costcrew-run`. A deployment that relied on the full prompt now sends masked data until it names `full`.
- A console whose `-addr` is not loopback refuses to start without `-behind-tls` or `-insecure-http`. On such an address every cookie is Secure whatever `-behind-tls` says, so a browser on plain HTTP from another machine gets no session.
- `.session-secret` must pass the owner and mode rule. Before 0.10.0 the console read the key whatever its owner or mode, and a read that failed for any reason replaced the key, which signed every session out. Now a key that fails the rule stops the start, and a key that cannot be read is left as it is.

## Migration

- **Prompt data.** Pass `-prompt-data full` or set `COSTCREW_PROMPT_DATA=full` to keep the old text, on `costcrew` and on `costcrew-run` alike. To take the masked default, keep `<data>/prompt-data.key`. Deleting it makes a new key, and every token changes.
- **Listener.** Put a TLS-terminating proxy in front of the console and set `-behind-tls`. Where plain HTTP on that address is deliberate, set `-insecure-http` (or `COSTCREW_INSECURE_HTTP`, where `1`, `true` or `yes` turn it on). `-insecure-http` lets the console start. It does not let a browser on another machine sign in over plain HTTP, so use TLS in front for any address people sign in from.
- **Session key.** If this account owns `<data>/.session-secret`, run `chmod 600 <data>/.session-secret`. If another account owns it, change the owner to the console's account, or replace a symbolic link with a plain copy of the key. A console that runs as root judges a root-owned key by the 0600 rule.

## What changed (#156, #157)

**Defaults and refusals (#157)**

- `-prompt-data` defaults to `masked`, the same default for `costcrew` and `costcrew-run`. The start log names the mode and whether it was chosen or is the default.
- `-insecure-http` (`COSTCREW_INSECURE_HTTP`) is new. A non-loopback `-addr` is refused without `-behind-tls` or `-insecure-http`, and a start on such an address logs that its cookies are Secure.
- Every cookie on a non-loopback listener is marked Secure. Loopback is unchanged.

**Session key (#157)**

- `.session-secret` is opened once with `O_NOFOLLOW` and `O_NONBLOCK`, and the open file is judged, not the path. A symbolic link, a fifo or anything else that is not a regular file refuses the start, and the refusal names `chmod 600`.
- The owner rule is PostgreSQL's `ssl_key_file` rule, as idryx and mockryx apply it. Windows skips the mode and the owner.
- Only a missing key is created, owner-only (0600).

**Dependencies (#156)**

- `agent-stack-go` v2 moves from v2.0.0 to v2.0.1.

**Tests and docs**

- Invariant 110 in `CLAUDE.md`: 25 new tests, 12 teeth cases and 17 scenarios in `features/safer-defaults.feature`.
- Stated counts restated: 1845 tests in 32 packages, 634 teeth cases, 646 scenarios in 77 files.
- README pins `v0.10.0` and describes the listener, the session key and the masked default.

## Not proven in this release

- No browser was run through a real TLS proxy, or over plain HTTP from another machine. The cookie behaviour is tested in code.
- No live model call was made under `masked`. The masked packets are checked against a fixture.
- No deployment or launcher was started against the new defaults. Each one that moves its image pin to 0.10.0 changes behaviour when it does.
- On Windows the session key's owner and mode are not checked, and a symbolic link is followed.
- The full web suite was not run under the race detector, as before.
